## Rules

- **Conformance is stated once, normatively** (STORAGE §17, SYNC §12, SEARCH §12; G1). Each part has a conformance section with one table of its profiles: reader, producer and owner, each holding the one before, with the sections, the statement directories and the vectors each owes; engine and connector; indexer and query client. An implementation MUST state each part's version and the profile it meets (`storage-draft-08 owner, sync-draft-07 engine, search-draft-08 indexer (canonical)`). objects.json binds every profile (a reader verifies what it reads, §7), payloads.json producers and owners, summaries.json an owner for each summary kind it writes; a connector owes SYNC §4 and what §5 and §8 ask of a listing, no vector binding it alone. STORAGE's opening, §16, SYNC's opening and SEARCH's opening cite the tables; GUIDE §1, vectors/README.md, OVERVIEW §11 and AGENTS.md no longer restate them. Guarded by checks/names.sh, which requires each part's table with exactly its profiles and every vector file owed by one (before: no table, every vector file owed by none).
- **The queue's payloads are typed** (STORAGE §15.3, §13 `payload`, Annex B.2; payloads/; G2). Each action and intent at `v` 1 has a JSON Schema (2020-12) at payloads/<action>.v<v>.schema.json, a top-level folder beside migrations/ and queries/ since a payload is wire format, not vector data: `add`, `set-flags`, `remove`, `move`, `copy`, `update`, `set-performer`, `submit`, `calendar-reply`, `calendar-cancel`, `collection-create`. `seq` an integer from 1, a body a name of §5, a flag set distinct flags of printable ASCII, `rcpts` non-empty, `partstat` one of three, an intent's `seq` and `link_id` one of two (`oneOf`). A payload missing a member its schema requires, stating one of another type, or holding one its version does not define is malformed: a producer MUST NOT enqueue it, an owner knowing the action and version MUST park it, an intent's performer likewise, never applying it in part nor ignoring a member; a member added takes the next `v`. The prose shapes keep their notation, now defined (`n`, `hash`, `key`, `id`, `collection`, `addr`, `label`, `text`, `[…]`, `[addr…]`, `?`, `( a | b )`), `"link_id": …?` becoming `key?` and `copy` written beside `move`. Guarded by checks/vectors.py, which reads every shape the documents write (STORAGE §15.3's bullets, Annex B.2's rows), refuses one naming no action or not reading, and requires each schema to be its shape member for member, optional where the schema requires none, typed as the placeholder says; and by vectors/payloads.json (`v` 1, vectors/schema/payloads.schema.json), 34 payloads valid or malformed, each validated against its schema, every schema with one of each. On the tree before (with the new schemas and cases copied in), the pseudo-JSON failed to read (`no placeholder '…'`, `no placeholder 'name'`) and four actions had no shape; seed: `add`'s schema without `additionalProperties: false` (refused: its shape differs, and the payload with an undefined member validates).
- **Annex B names every capability once** (Annex B, §14.2, §13, §15.6; G3). One table, Capability, Kind, Needed by, of every name this part defines: 30, no abbreviated row, `mail.submit.copy`, `calendar.reply.occurrence` and `calendar.cancel.occurrence` among them; B.1 keeps the definitions (flag change, scheduled, an online meeting asked for, an occurrence changed) and B.2 its payload table keyed by action. The naming rule now states what the names are: lowercase words joined by periods, the first the domain fixing the kind (`collection` every kind), then an object and a verb, a flag, a feature or an intent, one more word an intent's option. A name beginning with `x-` is an application's own and this part defines none, so `x-vtodo` is renamed **`calendar.component.vtodo`**, still read only where a row states it, the one name outside the base set the table marks; §15.6's declaration MUST and GUIDE §13's now name the base set, so an owner still writes the renamed row only where it knows the answer. `item_reference.role` is classified once: closed, its `CHECK` also taking any name in an application's `x-` space (§13, §14.2, which called it open). Guarded by checks/names.sh, which requires the table, each name of the grammar with the domain's kind and none `x-`, and every capability a document writes in backticks or invariants.sh binds to be a row of it, an abbreviated `.update` refused (before: 27 names outside any table, `.copy`, `.move`, `.remove`, `.update` and `x-vtodo` among them); seeds: `x-vtodo` bound again in a scenario, a row written `contacts.card.update`, `.remove` (both refused). The role's `CHECK` stays guarded by invariants.sh's "reference: a role outside the vocabulary, a bare or capital x-, and an unknown origin are refused". checks/names.sh reads checks/invariants.sh, which the flake's `standard` fileset now holds.
- **Security considerations** (STORAGE §18, §8, §9.2, Annex B.1; SYNC §12, SEARCH §6, §12; G4). Directories `0700`, files `0600` (index.db, the locks, `-wal`, `-shm` included), an owner-only ACL on Windows, a store others can read or write refused or opened on the user's word (SHOULD); write access is the trust boundary, every producer trusted as the owner, an owner MAY ask before performing an intent; read access suffices to hold a lock, and a lock file MUST be opened without following a link; a path derived from a file's or an attachment's name, a collection's name or a section MUST neutralise separators, `.` and `..`, NUL, control and bidirectional formatting characters, and stay in its directory; a producer enqueuing a resource the user did not write as it stands MUST remove every `X-PIMDIR-` property first; no credential in any column, the opaque ones named, error text scrubbed (extending §9.2); a store from elsewhere opened with `PRAGMA trusted_schema = OFF` and the defensive flag (SHOULD); a backup copies quarantine/ too (§8, batch 2's note). §18 points at the name checks, the no-replace write, verification and the bounds rather than restating them; SYNC §12 and SEARCH §12 point at it, and SEARCH §6's decrypted index is the user's opt-in, never a default. Guarded by invariants.sh, "untrusted: the canonical schemas' triggers and statements run with trusted_schema off and the defensive flag on", a guard holding on the schemas before (it failed there only on `optimize_text`, below). File modes, link-free opens, path neutralisation, the property strip, scrubbing and the backup's scope are program and filesystem behaviour no check here observes.
- **Erasure** (STORAGE §11.5, §4.1, §11.1; SEARCH §4, §3; `optimize_text`, new; G5). A purge removes a row, not its bytes. Every connection writing pimdir.db or index.db MUST set `PRAGMA secure_delete = ON`; an owner erasing an item runs its purge (or `delete_unbound_item`), the collector, the index refresh with the thread prune batch 6 landed and then `optimize_text`, which merges every segment of `object_text` and `summary_text`, and `PRAGMA wal_checkpoint(TRUNCATE)` on both files until every frame is checkpointed. A body another item names, a backup, quarantine/ and the filesystem's own copies stay. README's "only an explicit purge erases" now says what holds. Guarded by invariants.sh, whose harness now sets `secure_delete` on every connection it opens: "erase: a purged mail's key, subject and address leave pimdir.db, and its body's words index.db…" (before: `0|1`, no `optimize_text`), "erase: without optimize_text the deleted body's words stay in a full-text segment" and "erase: without secure_delete a purged row stays in the space its delete freed, in both files". Measured on SQLite 3.50.4: the zanzibar mail's word left 0 times in pimdir.db and 0 in index.db with both, 0 and 1 without the merge, 10 and 3 without `secure_delete`. FTS5's own `secure-delete` option was tried in place of the merge and left the term once in index.db (the segment index keeps a leaf's first term), so the merge stays. The WAL step is unobserved: the CLI harness checkpoints and deletes the WAL as each process closes.
- **Terms** (STORAGE §2, §14, §14.1, §15; SYNC §2, §3, §4, §5, §10, §11; G6). STORAGE §2 defines a placement once, the row of `items` keyed `(collection, link_id)` with its sources' bindings, SYNC §2 a **projected placement**, one source's view of one, which SYNC writes *placement* for short. **Kind** is a collection's media type, **summary kind** the summary table an item's row is in, **mutable** a card, a calendar resource and a file, **immutable** a message; an **action** is what the queue carries (§15's "kind" of an action is now "action", Annex B.2's column too) and SYNC's change kinds are **changes**. `load(collection, scope)` becomes `load(collection, selection)`, `All`, `Handles` and `Links` its **selection**, scope keeping its date window alone. Defined: writer, consumer, engine, connector (STORAGE §2), engine, connector, run, push (SYNC §2); "chips" became the read and attachment filters, in the prose and the four statements' comments, invariants.sh's scenario labels keeping the word earlier entries quote; SYNC's "hub" became another source's write. Wording no check observes.
- **Wording and checkability** (G7). GUIDE §1 cites STORAGE §15.3, README says "a local-first standard", OVERVIEW §8 counts seven actions and four intents, vectors/README.md carries `Status: informative`, cites STORAGE.md, SYNC.md and SEARCH.md for every section and writes no key word. SEARCH §8.3's ABNF reads tokens, `sep = 1*( SP / HTAB / CR / LF )` separating them and being none, its bullet saying two words are two terms only across one while a parenthesis or a phrase needs none; the reference parser already tokenised so, and vectors.py's grammar checks pass unchanged. SQL comments follow the prose: `contact_summary.fn` decoded (Annex A.2), `mail_summary.size` the body's octets else the source's figure (A.1), `mail_summary.sender` canonical (A.6), the search schema's header without its "same runner shape (§3)", and recompute_refcounts.sql without its benchmark, which this log keeps: on twenty thousand items the correlated-subquery form took 80 s against the grouped pass's 121 ms. Untestable MUSTs: SEARCH §6's "MUST be documented" became the user's opt-in, STORAGE §16's vendoring a SHOULD, §15.1's "any application deadline" a citation of §8. Guarded by checks/names.sh, which now requires each informative document (OVERVIEW.md, GUIDE.md, vectors/README.md, conventions/gtd.md) to say so on its Status line and write no key word (before: vectors/README.md's two **MUST** and no Status line).
- **A zone's rule is bounded** (STORAGE Annex A.3; batch 6's note). A `VTIMEZONE` observance's `RRULE` is followed for at most 1,000,000 periods from its `DTSTART`, counted as SEARCH §7 counts one, the last onset's offset standing beyond them. Annex A stays at revision 3, which no draft has released, the rule folded into it as batch 6 folded the walk's bound. Guarded by vectors/summaries.json, event-zoned-hostile.ics (a `DAYLIGHT` rule stepping every second from 1970 at +01:00, a `STANDARD` onset in 1980 at +00:00: 12:00 in June 2026 is `12:00:00Z`, 11:00:00Z unbounded), and checks/vectors.py, which reads the bound from A.3's prose and expands a rule stepping by a fixed span up to it. The earlier vectors.py refused the fixture ("a shape checks/vectors.py does not expand"); seed: the bound raised to 1,000,000,000,000 (refused).
- **A body's charset** (SEARCH §6, §2; batch 6's note). A text part SHOULD be decoded as Annex A.1 decodes an encoded word's octets (the WHATWG decoder its `charset` labels, no byte order mark, `us-ascii` when unstated, UTF-8 replaced when no label names one), and its text beyond seven-bit ASCII in another charset than UTF-8 is outside the hit-set guarantee, as HTML's reduction is. Pinning it as a MUST needs a vector the search store does not hold, and a new mail item there moves hand-written cases nothing re-derives, so the guarantee is scoped instead: a statement no check can observe; the vectors hold no such text.
- **Signatures match their statements** (STORAGE §14, GUIDE §14, conventions/gtd.md §2; G8). `lookup_objects(account, links)`, `held_mail_summary(account, link_id, object)`; GUIDE's and gtd.md's `set_collection_name(collection, '…')` and `set_collection_role(collection, '…')` written by name, the value in prose. Guarded by checks/names.sh, which reads every `name(args)` and every run of names before one `(args)` the documents write and requires the arguments to be the statement's named parameters and list slots, in any order, each once (before: the five above).
