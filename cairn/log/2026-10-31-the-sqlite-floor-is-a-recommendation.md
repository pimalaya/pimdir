# The SQLite floor is a recommendation, and the schema needs no JSON

The parts bound SQLite versions and extensions where they meant a model, and the Android app, which wants the platform's SQLite (3.18 on API 26, no JSON before 3.38, FTS3 and FTS4 only), was the first implementation they shut out. The floors are now what the canonical text needs, and the canonical text calls no JSON function. Lands in storage-draft-07, search-draft-07 and sync-draft-06 (cairn/changes/the-sqlite-floor-is-a-recommendation).

Rules, and the check guarding each:

- **Shapes** (STORAGE §4.1, §4.4, §6 step 2; SEARCH §2). SQLite 3.37 and the canonical text are RECOMMENDED for the store, 3.43 with FTS5 for the index. Another shape MAY run on any SQLite keeping the model: tables, column meanings, invariants, Annex A, statement effects, model vectors. A store names its shape in `store_meta.shape` (`pimdir` by default); a program refuses one it does not implement, and §6 reconciles the canonical shape alone. Guarded by invariants.sh (`store_meta: a store records the canonical shape by default`).
- **Flags as rows** (STORAGE §4.3, §4.5, §13, §14). `items.flags` and `bindings.base_flags` became `flags_known` and `base_flags_known` with `placement_flag` and `binding_base_flag`, keyed by the parent's key plus the flag, `WITHOUT ROWID`, `placement_flag_by_flag` for a flag predicate. A flag is non-empty printable ASCII without a space, by `CHECK`. An unknown set holds no row (`placement_flag_needs_known`, `items_forget_flags` and their base twins). A flag added or removed requests the placement's stamp, so a set written again as it was stamps nothing. Writes are `retain_flags` and `add_flags` (and the base twins) after the row; reads answer the set as one text joined by spaces, `''` known-empty, `NULL` unknown, so every read statement keeps its columns. `collect_before` compares the two sets with `EXCEPT` both ways. Guarded by invariants.sh, section "Flags are rows, read as a set": the empty and unknown reads, the stamp on a change and none on a restatement, a duplicate once, the refused space, control character and empty flag, the unknown set refusing a row and losing its rows, the rename and the cascade, and the base set's read and refusal.
- **Lists in their tables** (STORAGE §4.3, Annex A.1, A.4, §14.1). `mail_summary.in_reply_to` became `mail_in_reply_to` (`mail_in_reply_to_by_id`, which turns `list_replied` from a scan into a seek), `task_summary.categories` became `task_category`, each `(collection, link_id, position)` under its summary row. Read apart by `load_in_reply_to` and `load_categories`, as addresses are; written by `replace_in_reply_to`, `insert_in_reply_to`, `replace_categories`, `insert_category`. Guarded by invariants.sh (the `replied:` scenario and the task backfill, now writing and reading the rows).
- **List parameters** (STORAGE §4.4). The 27 `json_each(:list)` calls read `temp.param(slot, position, value)`, filled by `create_param`, `clear_param` and `bind_param` inside the statement's transaction; an optional list takes `:scoped`. The open item of the proposal is settled this way: the convention is written in STORAGE §4.4 as the canonical shape's, and another shape binds its lists as it chooses. Guarded by schema.sh, which prepares every statement with the table in place, and by every invariants.sh scenario passing a list.
- **The queue's targets** (STORAGE §4.3, §13, §14, §15.3). `queue.target_collection`, written by `enqueue_action`, read by the four queue loads, followed by `rename_queue_targets` as a plain `UPDATE`. The payload keeps the id it was enqueued with and the owner reads the column. Guarded by invariants.sh (`queue: a rename follows into a pending move`, `supersedes: a rename follows into a pending add's supersedes`).
- **Lossless rewrites**: `iif` to `CASE` (`add_reference`, `item_reference_collects_files`); §6 and SEARCH §2 compare `sqlite_master` text. `RETURNING`, upserts, `UPDATE … FROM` and `STRICT` stay canonical.
- **No JSON in the canonical text**: checks/schema.sh refuses any `json…(` call under migrations/ and queries/, which fails against storage-draft-06's text.
- **Reconciling draft-06** (STORAGE §6, GUIDE §3). The owner reads the four JSON arrays before the rebuild, by text of its own, and writes them after it with `backfill_flags_known`, `backfill_base_flags_known` and the list statements; a `NULL` set stays unknown. A reader of an unreconciled store reads a subquery over an absent table as answering none. A rebuilt queue takes each target from its payload (`backfill_target_collection`), and a row from a producer predating the column, its target `NULL`, is read from its payload and parks on a renamed id rather than land elsewhere. A flag the earlier draft held that §13 refuses refuses the reconciliation, naming it, the store left as it was. Guarded by invariants.sh (`reconcile: a set an earlier draft held lands in its tables once marked known`, `queue: a reconciled queue takes its target from the payload, row by row`).
- **The fold before the tokenizer** (SEARCH §5, §8; GUIDE §15). Index and query text is lowercased by Annex A.2's mapping, decomposed (NFD), stripped of the marks of U+0300 to U+036F and composed again, and the canonical tokenizer is `unicode61 remove_diacritics 0`, so no SQL function is registered. Relevance is the shape's own, bm25 RECOMMENDED; a shape without one may refuse `relevance`. Guarded by a new search case, `αθηνα` matching item 8, now "Budget Αθήνα": `remove_diacritics 2` folds Latin alone and keeps the Greek tonos (checked on SQLite 3.50: it also keeps `ø` and `Ł`, which the fold keeps too).
- **Model vectors** (STORAGE §16, SEARCH §11): objects, summaries, sync and search vectors bind every shape, a summary's lists stated as arrays; invariants.sh and schema.sh bind the canonical shape. A relevance-ordered search case binds its order only where the shape ranks by bm25.

Departures from the proposal, both reviewed here rather than with the user: the child tables are keyed by `(collection, link_id)`, as `item_address` is and as their parents are, not by `seq`; and the category table is `task_category`, its parent being `task_summary`, not `item_category`. The fold's mark range was chosen so a non-Latin vowel sign or point stays.

GUIDE §3, §5, §13, §14, §15 and OVERVIEW §1 and §10 follow. conventions/gtd.md names `task_category`, its version unchanged.
