# A query grammar that refuses what it does not read, chunks, the time zone database version

The pimdir side of cairn/changes/search-milestones, decided 2026-10-27: the query language is the surface an MCP layer hands to agents, so two parsers must agree on every query and a query neither understands must be refused with an error an agent can correct from, never read as free text. §8 was prose, and the 21 query vectors used no operator, wildcard, relative date, sort or threaded listing.

- **SEARCH §8.3, the grammar**: an ABNF over Unicode scalar values; `and`, `or`, `not` case-insensitive, `not` over `and` (explicit or by juxtaposition) over `or`, parentheses grouping; a `-` beginning a primary is `not` (the notmuch and Gmail habit agents carry, which free text read as the positive term), never inside a word, and one followed by whitespace, a `)` or the end is `dangling-operator`; a colon-bearing word outside quotes is a field term whose name must be in §8's table as written, else refused; a phrase runs to the next quote, literal (no field, operator or wildcard inside); a text with no token matches nothing; `*` only last, after two characters or more, on free text or a text field's value holding no `@`; `kind:`, `is:` and `has:` closed sets, `is:` now `unread`, `read`, `flagged`, `answered`, `draft`, `encrypted` (`tag:` and `flag:` take any flag). Guarded by the new queries.json cases (`-kind:mail kind:contact`, `-(...)` and the `-`, `reunion -`, `reunion - budget` refusals for the `-`, `stand-up` staying one text) and by checks/vectors.py, which now parses every query under the grammar.
- **SEARCH §8.4, refusals**: the JSON object `code`, `message`, `start`, `end`, `expected`, `fields`, offsets in characters; eight codes, each with its span; several faults answer one, the phrases, then the parentheses, then the terms and operators in reading order, the leftmost of the first pass to find one. Guarded by 39 refusal cases, each re-derived by checks/vectors.py.
- **SEARCH §8.1 and §8.2**: a range runs to the end of its last point's span; a single relative amount runs from its instant to `now`; a year is a point; dates resolve in the client's zone, UTC when none; a range leaves the horizon when it starts before or ends after it, an open side always (`horizon_left`). A file has no date, its `sort_key` being its name, and sorts last with the contacts by default: before, an open range matched a file and the default order put files first. The `name` sort is defined (the folded title, across kinds). `changed:` takes change stamps, which `items.changed` holds, not dates. Guarded by the cases `date:2w`, `date:today..`, `date:2026-08-04..2026-08-07`, `kind:task date:2026`, `date:..2025-01`, `changed:..1000000000`, `changed:2026-08-01`, the `forecast or reunion` ordered case and the `name` and `relevance` sorts.
- **SEARCH §6, chunks**: extraction records the chunk boundaries of `body` and `note` in the `chunk` table (`insert_chunk`, read by `chunks_of`), paragraphs at blank-line runs packed greedily into 1024 bytes, a longer one cut after its last whitespace within the limit, else at a character boundary; the rows cascade with the object. Shared with cairn/changes/embedding-index. Guarded by vectors/search/chunks.json, re-derived by checks/vectors.py, and by the chunk scenarios of checks/invariants.sh. The mail `attachment` field is now the attachments' names and media types (STORAGE §14.3), pinned by `has:attachment` against the invitation's inline calendar part.
- **SEARCH §7, the time zone database version**: `index_meta.tzdb_version`, `set_tzdb_version`; `items_to_reexpand` takes the version in use and returns every live calendar item when it is not the recorded one. Guarded by the tzdb scenarios of checks/invariants.sh, which fail against the previous statement.
- **Fixtures**: mail-reply.eml (a reply to item 1, a thread of two), mail-encrypted.eml (PGP/MIME), and mail-attachment.eml reused, as items 11 to 13 of vectors/search/store.json; item 3 gains `\Flagged`. No earlier case's answer moved but `kind:task date:..2026-10`, which now says `horizon_left`. The store is stated as an owner recording attachments leaves it (STORAGE §14.3, sync vector 70): item 13's stand-in, item 14 (`part:attach-1@example.org#2`, invoice.pdf) in the declared `home/\u0001attachments` collection (role `attachments`), and its `attachment` reference, so a store built through the owner path is the vectors' store; `changed:..1000000000`, `inv*`, the `name` sort, `not (...)` and `-(...)` gain item 14, pinned by the new case `linked:attachment:attach-1@example.org`. checks/vectors.py fails without the item, every case naming it.
- **SEARCH §8.2, coverage**: it counts bodiless live items only of the kinds whose body search reads (mail, contacts, calendars), never files, which §6 indexes from their summary alone: a store holding one attachment stand-in otherwise reported every answer incomplete for good, teaching an agent to ignore the flag. `coverage` excludes the file kind; queries.json's coverage drops `application/octet-stream`. Guarded by the coverage scenario in checks/invariants.sh.
- **SEARCH §4, a batch's cursor**: `load_changed_items` answers each row's `changed`, and a batch may record its last one as `store_change`, the purge count left as the previous pass recorded it, so an implementation committing bounded batches resumes after the last one without a statement of its own. Guarded by the feed scenario in checks/invariants.sh.
