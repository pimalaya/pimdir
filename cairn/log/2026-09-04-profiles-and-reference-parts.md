# Three profiles bind the store; the layers are the reference's

The three parts read as peers a second implementation was expected to meet in full. In practice a reader implements a few statements, a producer adds a queue append, and the owner, the engine and the index are one library, io-pimdir. The standard now says so.

STORAGE is normative by profile: reader, producer, owner, each a superset of the last, and GUIDE §1 is their checklist. SYNC carries the status reference: binding for the reference engine, descriptive for everyone else, what every writer owes being STORAGE §10 to §12. SEARCH splits along the same line, §8's query language normative for every client and the index reference. The statements sort into queries/storage/read/, queue/ and owner/ so a reader sees its whole job at once; vectors/README says which profile each set binds; README, OVERVIEW §11 and AGENTS follow.
