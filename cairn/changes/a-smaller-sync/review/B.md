## Findings

- o05-L256-s2. Base: "A source may list at most a number of members of a collection, whatever it holds (an IMAP server under a folder size limit listing the newest 1,000 of 1,900 messages), so a member past the cap is missing from every round, not once." Rewrite: absent (ledger: cut-informative). The sentence is the only definition of what "caps" means, and the MUST and MUST NOT of o05-L256-s3 ("MUST set `capped` ... and MUST NOT set it otherwise") are conditioned on it; without it nothing separates a cap (a count limit, whatever the collection holds, missing from every round) from a page size, a timeout or a one-off truncation, so the boundary of when `capped` must and must not be set is now undetermined. Severity: weakened.

- o05-L292-s2 with o05-L288-s2 and o05-L290-s1. Base: "A round whose last page is `narrowed` (§4) MUST find absent only a member, in its scope as above, whose handle the `enumerated` list that page hands lacks." ("as above" carrying "or is unknown and the round is no band round"). Rewrite, table C row "`narrowed`, with `enumerated`", undated column: "same". The base's band exclusion rides on "in its scope as above"; the row's "same" points at the dated cell only, so for a narrowed band round handing `enumerated` (which o05-L254-s5 explicitly asks for, "on a band round's last page as on any other") the band exclusion now lives only in a different row, and the table gives no rule for which row wins when a round matches two. Literal reading stays equivalent ("only when" is a limit, never a licence), but the overlap is a trap for an implementer. Severity: wording.

- o05-L307-s1. Base: "A parked round drops nothing and writes no `CloseRound`." Rewrite, table C row "parked": Stated removals cell empty; "no: it drops nothing" in the column "An in-scope dated member unlisted"; "no: it writes no `CloseRound`" under Closes. The base's "drops nothing" is unqualified, the rewrite confines it to absences; this agrees with o04-L138-s4 ("A stated removal is applied on any page ... no guard counts it") and §11's invariant ("dropped but for a removal its remote stated, an absence from a round the run closed (in that round's scope and not parked)"), so no requirement moved, but the empty Stated removals cell is the one row that does not say "applied" where the base, read as a whole, applies them. Severity: wording.

- o04-L127-s1 with o04-L181-s1. Base: "`vanished`: the handles the source states removed;" Rewrite, §4 table row `vanished`, On which pages: "every page". The base never located `vanished` on every page and states that "A band head carries no checkpoint and no vanished handle"; "every page" reads as the field being present on a band head too, only harmless if read as an empty list. Severity: wording.

- o05-L254-s2. Base: "A filter lists a member only when it matches, and no margin makes a filter on another date than the `Date` list a superset of the scope: ... and a server reading the `Date` itself may skip an undated one." Rewrite: absent (cut-informative). Its last clause is what tells a connector that a `Date`-based filter (IMAP `SENTSINCE`) narrows too; the kept "by any date filter" still binds that, so nothing is lost. Severity: wording.

- o08-L540-s2 and o08-L540-s4. Base: "A rekey whose listing names no member parks the same way while any based binding of this source is absent, whatever their number (§5, an empty listing)." Rewrite: "A rekey MUST NOT be written where §5's mass-absence or empty-listing guard would park a round (table C), unless the run carries the `accept_absences` option." §5's empty-listing guard is phrased through stamps ("so that no binding carries its id once its last page lands"), which a rekey does not write; the rekey case now holds only by analogy where the base stated it outright. Same scope and level. Severity: wording.

- o05-L294-s3. Base: "the run MUST report how many based bindings it left unlisted, counted as the deletes above count them, as a narrowed round handing no enumeration does." Rewrite, table C row `capped`, Reports: "the run MUST report the unlisted count, as a narrowed round handing no enumeration does". The counting rule survives only through the cross-reference to the row above. Severity: wording.

- o10 table D (o05-L400-s3, o10-L630-s2 context). Base: "The last page of a round and a rekey ask for the whole collection" and "A page before the last and a head ask for `Handles` ... and `Links`". Rewrite, table D row "a page": Load "`Handles`, `Links`", the label not excluding the last page, while row "a round's last page" says "the whole collection". The bullet list above the table still decides it; the table alone contradicts itself for the last page. Severity: wording.
